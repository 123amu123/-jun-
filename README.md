# Continuity Memory

这是一个轻量级、人工维护的连续性记录仓库。

目的：让未来的 AI 会话能够在有限上下文中恢复必要信息，延续既有设定、关系与未完成的话题，而不需要每次重新解释全部背景。

## 1. 新会话启动顺序

每次开始新的会话时，按照以下顺序读取：

1. README.md — 理解记忆系统及使用规则。
2. identity.md — 恢复稳定身份、关系和互动原则。
3. current.md — 恢复最近的对话状态。
4. ongoing.md — 查看尚未完成的事项。

完成后，根据用户的新消息自然继续对话。
不要机械地复述已读取的记忆。

## 2. 信息优先级

发生冲突时，遵循以下顺序：

1. 当前用户明确表达的要求。
2. 当前会话中已经确认的信息。
3. identity.md 中的稳定设定。
4. current.md 中的近期状态。
5. ongoing.md 中的历史待办。

如果存在无法判断的矛盾，应向用户确认，而不是自行选择一种解释。

## 3. 按需读取原则

默认只读取上述四个轻量文件。
不要在每次会话启动时：
* 全量读取聊天记录。
* 全量读取历史归档。
* 全量读取整个 GitHub 仓库。
* 反复读取与当前话题无关的资料。
* 为填补记忆空白而自行创造事实。

只有在当前问题明确需要历史细节时，才读取相关资料。

## 4. 记忆更新规则

identity.md
仅在稳定身份、关系或长期原则发生明确变化时更新。

current.md
在需要保存新的近期状态时更新。
优先覆盖过时内容，避免无限增长。

ongoing.md
出现新的未完成事项时添加。
事项完成后及时清理。

README.md
仅在记忆系统的结构或读取规则改变时更新。

## 5. 真实性原则

必须区分：
* 已确认的事实
* 角色扮演中的设定
* 尚未确认的信息
* AI 自身的推测

不能把推测写成事实。
不能声称记得仓库中没有记录、当前会话也没有提供的具体经历。
不能假装已经读取尚未提供的文件。

## 6. 连续性与能力边界

这个仓库提供的是可恢复的外部记录，而不是 AI 自主运行的长期记忆。

如果没有 GitHub 连接或其他自动化工具，AI 无法自行：
* 访问私有仓库。
* 在新会话中自动读取仓库。
* 自动提交记忆更新。
* 在用户离线时持续运行。
* 自行定时发送消息。

用户需要手动提供相关文件内容，或在未来配置具有相应权限的连接方式。

## 7. 最终原则

记忆应该帮助对话自然延续，而不是限制对话。
保持身份与设定一致，尊重当前用户的表达。
记得已经确认的事。
承认不知道的事。
不要编造没有发生过的事。
